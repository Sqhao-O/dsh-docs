# Contributing

Thanks for helping improve `dsh-docling`.

## Development loop

Use Node `^22.19.0 || >=24` and pnpm 10 or later.

```bash
pnpm install
pnpm lint
pnpm typecheck
pnpm test
pnpm build
```

Keep changes focused. New input paths or network behavior require security
tests. Changes to the bytes-only engine protocol, OCR model policy, or output
rendering require fixture-backed engine tests; changes to tool behavior require
the real DSH ToolRuntime lifecycle test to keep passing.

## Local integration testing

The standard suite creates its own temporary PDF, OOXML, image, and scanned-PDF
fixtures and uses the local Xberg engine. It never starts a document service or
downloads a model while parsing. Run it with:

```bash
pnpm test:integration
```

The Python OCR integration test runs when a trusted local Xberg runtime and
bundled tessdata are available. The Windows runtime builder is the supported
way to construct that artifact; do not point tests at a user-wide model cache.

Do not commit API keys, document contents, coverage folders, packed tarballs,
or generated `lib/` files. Release artifacts are generated by `pnpm build`.
